## No-repair reproduction path

For the next PR that follows the same shape as #337 (modifying universal-lane source `.apm/instructions/master.instructions.md` and the compiled `CLAUDE.md` / `AGENTS.md`, with PRD-side wording also requiring a matching update in `docs/agent-rules-design-philosophy.md` glossary section 2.5 and / or the section 3 matrix), the path to a one-commit repair-free merge is:

1. **Plan phase**: enumerate every PRD-side text location that mirrors the master Section being edited. For Section 2 (`Bound Inputs and Unknowns Before Coding`), the mirrors are at least: PRD section 2.5 glossary entry `untrusted data`, and PRD section 3 matrix `P2 - input and pre-code reasoning` row's `Universal text owns` cell. Treat them as part of the same change-set in the plan, not as follow-ups. Decide bullet count and density up front before drafting wording (so a `refactor verbosity` self-revision does not become a separate commit).
2. **Edit phase**: in a single commit, modify master Section X, regenerate the compiled `CLAUDE.md` / `AGENTS.md` via `apm compile` (apm-cli pinned), and update every PRD mirror identified in step 1. Keep `Refs #` (or `Closes #`) consistent across the commit message and PR body. Do NOT add a new required glossary term (`governance-gated provenance` was deliberately deferred in PR #337) without a separate harness issue, because adding a term changes the contract of `REQUIRED_GLOSSARY_ENTRIES` in `scripts/scan_design_philosophy_drift.py` and that is its own scope.
3. **Local verify phase**: run the full local gate set before opening the PR:
   - `uv sync --locked && uv run --with "apm-cli==<pinned-version>" apm compile` -- confirm zero-diff against `CLAUDE.md` and `AGENTS.md`.
   - `python3 scripts/scan_apm_portability.py verify --path .apm/instructions/master.instructions.md --path CLAUDE.md --path AGENTS.md` -- confirm exit 0 (no repo-local tokens in universal text).
   - `python3 scripts/scan_design_philosophy_drift.py verify --master .apm/instructions/master.instructions.md --doc docs/agent-rules-design-philosophy.md` -- confirm exit 0 (row count, label parity, glossary presence all pass).
   - `LC_ALL=C grep -nP "[^\x00-\x7F]" docs/agent-rules-design-philosophy.md .apm/instructions/master.instructions.md CLAUDE.md AGENTS.md` -- confirm the only non-ASCII characters are the authorised typographic ones (em-dash, en-dash, smart quotes) already present in the universal lane.
4. **Test phase**: `uv run pytest -q` and quote the pass count and total coverage in the PR body's `## Verification` block.
5. **Body phase**: copy `.github/PULL_REQUEST_TEMPLATE.md` and fill every section in order. Cite the closing issue with `Closes #NN` on the `Related Issue` line. Tag every assumption that is operator judgement (e.g. bullet density, naming choices, portability phrasing) with `Speculation:` in `## Assumptions` so reviewers can refute or accept each one independently. Record the build IDs before and after `apm compile` in `## Facts` so the artifact-source pairing is explicit. Keep the body ASCII-safe.
6. **CI phase**: open the PR. The `verify-title-policy`, `verify-body-policy`, `verify-issue-link`, `verify-apm-drift`, `verify-apm-portability`, `verify-design-philosophy`, `scan-non-ascii`, `verify-agents`, `lint-scripts`, and `gate.yml` (pytest) gates run automatically. CI green means ready for merge. Do NOT add post-open self-revisions for verbosity or PRD alignment; both should be resolved in step 1's plan-phase and folded into the single commit produced in step 2.

The s2 `refactor verbosity` and s3 `align PRD` commits on PR #337 are exactly the steps that step 1 above is designed to eliminate from the post-open window.

## Framework observation

Two observations about the harness, recorded here for the next iteration of the deterministic-gate set:

- **PRD-wording-vs-master-wording equivalence is currently a manual discipline.** The drift scan enforces row count, label parity, and glossary entry presence, but two PRD locations (glossary entry body text and matrix-cell `Universal text owns` content) are free text below the gated invariants. The s3 PRD-align self-revision on PR #337 illustrates the gap: a master Section 2 wording edit propagated to compiled artifacts via `apm compile`, but the PRD mirrors required a separate operator-driven commit. A future drift-scan extension could optionally map a master section-2 bullet set to specific PRD locations and compare normalised wording. Cost: introduces a new coupling between master-section-bullet-IDs and PRD-mirror-IDs that the harness has so far avoided. Benefit: closes the s3-class gap. Trade-off recorded; not auto-filed.
- **The `open-retro` workflow correctly fired on a zero-review-comment merge whose only commits were operator self-revisions.** The `has_review_comments` skip rule from PR #254 specifically scopes to review-comment count, not commit-count or self-revision detection. PR #337 having three commits but zero review comments is exactly the case the rule covers (skip would be wrong because the operator may still want a retrospective on the self-revision pattern). This retro is the proof that the rule's current scope is correct.
