# APM-managed paths

APM (Agent Package Manager) compiles this repository's universal agent
instructions and the pinned upstream skill dependency into several committed
trees. Those trees are **generated artifacts**: `apm compile` overwrites them
from their source of truth on every run. Editing them directly is a silent data
loss; the change is lost the next time anyone compiles, with no error.

This standard lists the APM-managed prefixes, explains why direct edits are
forbidden, and gives the one correct change procedure. Refs #2066, #1892,
#1891.

## Gated paths

A deterministic PreToolUse gate (`scripts/gate_agents_skills_edit.py`) blocks
`Edit` / `Write` / `Bash` tool calls that target these prefixes before the file
is touched:

| Prefix              | Source of truth                              | Regenerated by |
| ------------------- | -------------------------------------------- | -------------- |
| `.agents/skills/`   | `obra/superpowers` pin in `apm.yml` / `apm.lock.yaml` | `apm compile` |
| `.claude/skills/`   | `obra/superpowers` pin in `apm.yml` / `apm.lock.yaml` | `apm compile` |

Both directories are the two committed copies of the upstream
`obra/superpowers` APM dependency, expanded so Claude Code on the Web, Devin,
and Codex all load the pinned skills from a fresh clone (`.claude/skills/` is
the `#1983` carve-out; `.agents/skills/` the `#728` one). The two prefixes are
byte-for-byte the same set that `scripts/scan_repo_em_dash.py` and
`scripts/scan_repo_double_hyphen.py` already exclude in their `_SKIP_PREFIXES`.

## Other APM-generated files (governed separately)

`CLAUDE.md` and `AGENTS.md` are also generated by `apm compile` (each carries a
"generated by APM CLI. Do not edit manually" footer). They are **not** covered
by `gate_agents_skills_edit.py` because they are the trusted instruction files
governed by the code-owner merge gate: their source lives in
`.apm/instructions/`, and changes flow through that gate, not through skill
regeneration. They are listed here only so the full APM-generated surface is
visible in one place.

## Why direct edits are forbidden

- **Silent overwrite.** `apm compile` regenerates the managed trees from the
  pin. A hand edit under a managed prefix is discarded on the next compile, with
  no diff and no warning.
- **Single source of truth.** The pinned dependency (`apm.yml` /
  `apm.lock.yaml`) is the only place a skill's content is authoritatively
  defined. Editing the generated copy creates drift between the pin and the
  files on disk.
- **Observed incident.** Retro #1892 traced PR #1891 (a bulk em-dash
  replacement) editing 20 files under `.agents/skills/` before human review
  caught it. This gate is the deterministic backstop that incident asked for.

## Correct change procedure

To change skill content under a managed prefix, change the source, not the
generated files:

1. **Open an issue** describing the change (CLAUDE.md section 3: an issue
   precedes any branch, commit, or PR).
2. **Update the pin.** Bump the `obra/superpowers` dependency in `apm.yml` and
   `apm.lock.yaml` to the revision that carries the desired skill content. (If
   the change must originate upstream, land it in `obra/superpowers` first, then
   bump the pin here.)
3. **Run `apm compile`** to regenerate `.agents/skills/` and `.claude/skills/`
   from the updated pin.
4. **Commit the regenerated output** together with the pin change, citing the
   issue number.
5. **Open a PR** and drive it to a terminal state as usual.

If `gate_agents_skills_edit.py` blocks a tool call, its deny reason names the
blocked path and points back to this procedure. Do not work around the gate by
editing the generated files through an unmatched path; fix the pin and
recompile instead.
